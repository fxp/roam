🌉 跨源 Agent：隔着两个域名操作一篇真实文章

这个页面本身就是 roam.xiaopingfeng.com，点击下面的按钮会在一个独立的新窗口/标签页里打开 xiaopingfeng.com/deepdive/ 下一篇真实发布的文章。两个不同的域名， 浏览器的同源策略决定了这个页面对新窗口里的 DOM 没有任何直接访问权限—— 我自己在 devtools 里试过读那个窗口的 location，直接被拦截报错。

唯一的通道是我在文章页面里加的一小段 接收器脚本， 只信任来自 roam.xiaopingfeng.com 的消息，靠 postMessage 收发—— 跟 window.open() 打开的独立窗口通信，和跟 iframe 通信走的是同一套 postMessage 机制，这也是几乎所有"第三方登录弹窗"（Google/GitHub OAuth）背后用的手法。 左边的 Agent 有三种推理来源可选：本地用 WebLLM 在浏览器里跑一个小模型（WebGPU 推理，不发送任何数据到服务器）；云端 API 是任意 OpenAI 兼容接口 （OpenRouter / 智谱 BigModel 等）；本机 Ollama 则是直接连你自己电脑上跑的模型。后两种的 Key/地址 只存在你自己浏览器的 localStorage，请求直接从浏览器发到你填的地址，同样不经过 roam.xiaopingfeng.com——Ollama 那条路径亲测下来能明显更稳：本地 1B/1.7B 小模型 常选错工具、编造数字，换成本机一个 30B 级别的 Ollama 模型后，同样的多步任务全部一次做对。 不管哪种，模型自己决定该调用哪个工具去读文章、 数关键词、找到某一段并高亮——协调过程全程没有我的后端服务器参与。
