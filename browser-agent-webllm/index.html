🌉 跨源 Agent：隔着两个域名操作一篇真实文章

这个页面本身就是 roam.xiaopingfeng.com，点击下面的按钮会在一个独立的新窗口/标签页里打开 xiaopingfeng.com/deepdive/ 下一篇真实发布的文章。两个不同的域名， 浏览器的同源策略决定了这个页面对新窗口里的 DOM 没有任何直接访问权限—— 我自己在 devtools 里试过读那个窗口的 location，直接被拦截报错。

唯一的通道是我在文章页面里加的一小段 接收器脚本， 只信任来自 roam.xiaopingfeng.com 的消息，靠 postMessage 收发—— 跟 window.open() 打开的独立窗口通信，和跟 iframe 通信走的是同一套 postMessage 机制，这也是几乎所有"第三方登录弹窗"（Google/GitHub OAuth）背后用的手法。 左边的 Agent 用 WebLLM 在浏览器本地跑一个 1B 参数小模型（WebGPU 推理，不发送任何数据到服务器）， 自己决定该调用哪个工具去读文章、数关键词、找到某一段并高亮——全程没有后端服务器参与协调。
